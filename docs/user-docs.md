
# Document URLs and Sharing

This document explains how document identification works in the collaborative editor, how to share documents, and the technical decisions behind the implementation.

---

## How Document IDs Work

### Creation

When you visit `http://localhost:8080/` without any parameters, the editor:

1. Creates a new Automerge document using `repo.create()`
2. Automerge generates a unique document ID (e.g., `P8ikUBLFpvXuVSCVWyiBec9U54Y`)
3. The URL updates to include the document ID: `?doc=P8ikUBLFpvXuVSCVWyiBec9U54Y`
4. The document is saved to IndexedDB for persistence

### Format

Document IDs are base58-encoded strings generated by Automerge. They are:
- Approximately 25-35 characters long
- Cryptographically unique
- Content-addressable (tied to the document's creation)

Example URL:
```
http://localhost:8080/?doc=P8ikUBLFpvXuVSCVWyiBec9U54Y
```

### Persistence

Documents are stored in:
- **IndexedDB** (browser): Local persistence, survives page refresh
- **Sync server** (network): Shared with other connected clients

When you revisit a document URL, the editor:
1. Parses the `?doc=` parameter
2. Calls `repo.find(documentId)` to load the document
3. Waits for the document to load from IndexedDB or sync server
4. Displays the content in the editor

## Finding the Document ID

### In the URL

The document ID is in the URL after `?doc=`:
```
http://localhost:8080/?doc=P8ikUBLFpvXuVSCVWyiBec9U54Y
                           ^^^^^^^^^^^^^^^^^^^^^^^^^^^
                           This is the document ID
```

### In the UI

The document ID is displayed (truncated) in the toolbar:
```
Doc: P8ikUBLFpvXu...
```

Click on the truncated ID to copy the full shareable URL to your clipboard.

### In the Console

For debugging, you can access the document ID in the browser console:
```javascript
console.log(window.automergeHandle.documentId);
```

## Sharing Documents

### Method 1: Copy URL from Browser

Copy the full URL from your browser's address bar and send it to collaborators.

### Method 2: Click to Copy

Click on the "Doc:" label in the toolbar. The full URL is copied to your clipboard and the label briefly shows "Copied!".

### Method 3: File Menu

Use File > Copy Document URL to copy the shareable link.

### What Collaborators See

When someone opens your shared URL:
1. Their browser connects to the sync server
2. The document loads from the server (or their local IndexedDB if they've visited before)
3. They see the same content you see
4. Any edits sync in real-time between all connected users

---

## Make a Copy Feature

The "Make a copy" feature (File > Make a copy) creates a duplicate of the current document:

1. Captures the current document content
2. Opens a new browser tab
3. Creates a new document with a new ID
4. Pastes the content into the new document

The copy is completely independent - it has its own document ID and does not sync with the original.

## Technical Implementation

### Why Not Room Names?

The previous implementation used human-readable room names:
```
http://localhost:8080/?room=my-team
```

This required a registry to map room names to document IDs. The registry approach failed because:

1. **Automerge document IDs cannot be deterministic** - You cannot create a document with a pre-determined ID
2. **Chicken-and-egg problem** - How do clients find the registry document without knowing its ID?
3. **Race conditions** - Multiple clients creating the same room simultaneously

### Current Approach: Direct Document URLs

The current implementation uses Automerge document IDs directly:
```
http://localhost:8080/?doc=P8ikUBLFpvXuVSCVWyiBec9U54Y
```

Benefits:
- **Fully decentralized** - No central registry needed
- **Content-addressable** - Document ID is cryptographically tied to the document
- **Works with Automerge's design** - Uses the library as intended
- **PromiseGrid compatible** - Aligns with content-addressable storage model

Trade-offs:
- URLs are longer and not human-readable
- Users must explicitly share URLs (no "join room by name")

### Code Flow

1. **URL Parsing** (`src/app.js`):
   ```javascript
   const urlParams = new URLSearchParams(window.location.search);
   const docParam = urlParams.get('doc');
   ```

2. **Document Loading/Creation** (`src/setup/automergeSetup.js`):
   ```javascript
   if (documentId) {
     // Load existing document
     handle = await repo.find(documentId);
   } else {
     // Create new document
     handle = repo.create();
     // Update URL with new ID
     window.history.replaceState(null, '', `?doc=${handle.documentId}`);
   }
   ```

3. **Sync** (automatic via Automerge Repo):
   - `BrowserWebSocketClientAdapter` connects to sync server on port 1234
   - `IndexedDBStorageAdapter` persists to browser storage

## Future Considerations

### PromiseBase Integration

When PromiseBase (PromiseGrid's storage layer) is available, document IDs could become content addresses in the distributed hash table. The current architecture is designed to be compatible with this transition.

### Human-Readable Names

If human-readable document names are needed in the future, options include:
1. **Server-side registry** - Central server maps names to document IDs
2. **DNS-like system** - Decentralized name resolution
3. **URL shortener** - External service to create short links

These would be additions to the current system, not replacements.

## Troubleshooting

### Document Not Loading

If a document URL doesn't load:
1. Check if the sync server is running (`make ws`)
2. Verify the document ID is correct (no typos)
3. Check browser console for errors
4. The document may not exist if it was never synced to the server

### Content Not Persisting

If content disappears after refresh:
1. Check IndexedDB in browser DevTools (Application > IndexedDB > automerge)
2. Verify the sync server received the document
3. Check console for Automerge errors

### Multiple Users Not Syncing

If collaborators don't see each other's changes:
1. Verify both users have the exact same URL
2. Check that both are connected to the sync server (console shows WebSocket connected)
3. Check awareness server is running (`make awareness`)
